## 02 子赛道设置

子赛道 B：vLLM-Omni 推理优化
基于 vLLM-Omni 完成 MiniCPM-o 4.5 的适配、部署与性能优化，重点降低每个 chunk 的 RTF 与 TTFT，TTFP，提升模型的实时生成效率和首次响应速度。

指定模型：MiniCPM-o 4.5
指定推理框架：vLLM-Omni
镜像版本：vllm-omni:v0.25.0（Atlas A3/910C 官方镜像：quay.io/ascend/vllm-omni:v0.25.0-a3）
优化目标：在保证模型精度与 Demo 可用性的前提下，同时降低流式语音生成过程中的每个 chunk RTF 与 TTFT，提升模型的实时生成效率和首次响应速度。
核心性能指标一：每个 chunk 的 RTF

RTF 用于衡量生成一个音频 chunk 所消耗的计算时间与该音频 chunk 实际时长之间的比例。RTF 越低，表示流式音频生成速度越快，实时性能越好。

核心性能指标二：TTFT

TTFT，即 Time to First Token，用于衡量系统从接收到请求，到模型输出首个有效 token 所需要的时间。对于全模态流式交互场景，TTFT 直接影响用户感知到的首次响应速度。TTFT 越低，表示模型越快开始返回结果，首响体验越好。TTFT 的起止时间、预处理阶段是否计入、首个有效 token 的判定方式等，以官方评测脚本和最终评测文档为准。

核心性能指标三：TTFP

TTFP（Time to First Packet，首包时延）用于衡量系统从接收到请求，到模型输出第一段可用音频（首个 audio chunk / packet）所消耗的时间。在全模态流式交互场景中，TTFP 直接决定用户感知到的"开始出声"的快慢。TTFP 越低，表示流式语音越早开始播放，首响体验越好。


## 03 性能赛评测规则
本赛道采用"先满足准入条件，再比较实时性能"的评测方式。参赛方案只有同时满足精度要求和 Demo 可用性要求，才能进入对应子赛道的性能评测与排名。

一、准入条件：精度达标
优化版本相对于该子赛道官方基线版本的精度降幅必须满足：不超过 2 个百分点。

基线精度为 85%，优化后精度不得低于 83%
基线精度为 70%，优化后精度不得低于 68%
主办方将通过 Daily-Omni、TTS-Seed、Video-MME 等官方指定 Benchmark，对优化后的模型进行精度和能力验证。

如优化版本出现以下情况，将不能进入性能排名：

精度降幅超过规定范围
模型核心能力出现明显下降
输出结果异常
无法完成指定 Benchmark
修改模型行为，导致评测结果失去可比性
不同框架使用各自对应的官方基线，不跨框架比较精度降幅。

二、准入条件：Demo 可用
优化版本必须能够正常接入该子赛道指定的官方 Demo，并完成稳定的端到端运行。

llama.cpp-omni Demo 代码仓库：https://github.com/OpenBMB/MiniCPM-o-Demo
vLLM-Omni Demo 获取方式详情请参考文档：在昇腾 NPU 上部署 MiniCPM-o 4.5
主办方将重点检查：

模型服务能否正常启动
Demo 能否正常连接推理服务
音频、视频和文本输入是否能够正常处理
模型输出是否完整
流式语音输出是否连续
是否存在明显卡顿、中断或异常退出
是否能够完成官方指定的完整交互流程
连续运行过程中是否保持稳定
仅能运行 Benchmark、但无法正常接入 Demo 的方案，不满足本赛道的准入条件。
