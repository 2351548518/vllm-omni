## 一、踩坑速查（全部为实测，2026-08-13）

### 环境依赖类

| 症状 | 根因 | 修复 |
| --- | --- | --- |
| pytest「收集完 0 执行」（0.07s 结束、无 passed/failed） | 缺 `pytest-asyncio`；pyproject `asyncio_mode=auto` + `--strict-config` 使 session 无法启动 | `pip install pytest-asyncio` |
| Daily-Omni 测试被 skip | 缺 `datasets` | `pip install "datasets==3.6.0"`（版本与 pyproject 锁一致） |
| WER 评估报 "needs jiwer and zhon" | 缺评估依赖 | `pip install jiwer zhon` |
| 多进程服务启动挂死/卡住 | `VLLM_WORKER_MULTIPROC_METHOD` 未设 spawn | `export VLLM_WORKER_MULTIPROC_METHOD=spawn`（每次 shell 都要） |
| `pip install step-audio2` 后 torch 异常 | 依赖覆盖了昇腾匹配的 torch/torch_npu | `pip install step-audio2 --no-deps`；红线：**永不升级 torch/torch_npu/CANN/vLLM** |

### 服务启动类

| 症状 | 根因 | 修复 |
| --- | --- | --- |
| 服务启动访问 `huggingface.co` 报 `Network is unreachable` / `LocalEntryNotFoundError` | model id 是 Hub 名（pytest fixture 默认 `openbmb/MiniCPM-o-4_5`），远端无公网 | 设 `VLLM_TEST_MINICPMO_4_5_MODEL=/workspace/shared_assets/models/OpenBMB/MiniCPM-o-4_5` 或直接传本地路径 |
| Stage 0 启动卡死：进程 `D` 状态 + `lock_page`，rchar 不增长，900s 超时 | 模型在 fuse.glusterfs 只读共享盘，IO 抖动/网络盘慢 | **模型复制到本地盘**：`cp -a <共享盘模型> /root/models/`（19GB，一次性）；服务指向本地路径 |
| 重启报 `OSError: [Errno 98] Address already in use` | 旧服务残留 | 旧服务入口是 `vllm` 可执行文件，`pkill -f vllm_omni.entrypoints` **匹配不到**；用 `kill -9 <APIServer PID>`（`ss -ltnp | grep 8091` 查 PID） |
| bench 请求全部 **404**（服务端 `The model <路径> not found`），`Total input tokens: 0` | 服务加了 `--served-model-name openbmb/MiniCPM-o-4_5`，bench 请求 body 的 `model` 字段是本地路径，不匹配 | **服务不要加 `--served-model-name`**（官方 pytest 行为：served model 即本地路径） |

| 症状 | 根因 | 修复 |

### 进程与结果类

| 症状 | 根因 | 修复 |
| --- | --- | --- |
| `pkill -f "vllm serve"` 命令 exit 255 无输出 | pattern 出现在**自身命令行**，pkill 杀掉了自己的 shell | 正则技巧 `pkill -f "vllm [s]erve"`，或按 PID kill |
| bench 子进程退出 `SIGABRT` / `corrupted size vs. prev_size` | glibc 堆损坏（框架/驱动侧，退出时触发） | **不影响结果**：`--save-result` 已先落盘；以 result JSON 为准，忽略驱动返回码/`CalledProcessError` |
| 一次性 pytest 组合跑三套精度全废（32 分钟 0 有效） | Daily/Seed/duplex 共用一个 `omni_server` fixture，任一服务启动超时（900s）拖垮整轮；且 `-k` 可能误选 duplex | **分别独立跑**：用官方驱动 `tests/e2e/accuracy/qwen3_omni/run_qwen_omni_acc_benchmark.py`，每套单独起服务 + 单独 bench |
| pytest 内 fixture 启动超时但服务本身正常 | fixture 等待期与解压/IO 争抢 | 先确认 NPU 空闲、无 unzip/大 IO 任务再起服务 |

## 二、注意事项（运行纪律）

1. **改任何东西前先冻结基线**：manifest（镜像/commit/模型路径/部署 YAML sha256）已归档 `baseline_artifacts/env/manifest.json`。
2. **A/B 单变量**：每次只改一个参数；每个候选保留独立 YAML 或独立 commit，可回退；无法解释的结果不进主分支。
3. **精度跑法**：三项 Benchmark 的模型、prompt、采样、pack mode、帧数必须与官方一致；禁止改模型/采样/模板/输入数据刷分，禁止缓存或预生成回答。
4. **性能口径**：成绩以官方脚本为准；内部 trace 只做归因（`TTFP_internal` ≠ 官方 TTFP）；profiler 开销不算性能；910B 数字与 910C 官方基线不可直接比较。
5. **每次运行保存**：服务日志、配置、manifest、原始 JSON（`--save-result`）、逐条 eval items、失败请求。
6. **后台任务模板**（SSH 断了也活着）：
   ```bash
   setsid nohup <命令> > /workspace/results/minicpmo45/baseline/logs/<name>.log 2>&1 < /dev/null &
   ```
7. **端口与进程**：服务端口固定 8091；停服务先 `ss -ltnp | grep 8091` 拿 PID 再 `kill -9`。
8. **磁盘纪律**：模型/大文件放本地盘（`/root/models`、`/workspace/user_data/`）；共享盘只读且 IO 不稳。
9. **评测环境变量速查**：
   - 本地模型：`VLLM_TEST_MINICPMO_4_5_MODEL`（pytest 场景）
   - 本地数据：`VLLM_SEED_TTS_DATASET_PATH`、`VLLM_DAILY_OMNI_QA_JSON`、`VLLM_DAILY_OMNI_VIDEO_DIR`、`VLLM_VIDEOMME_DATASET_PATH` / `VIDEOMME_ROOT`
   - 离线评测：`HF_HUB_CACHE`、`HF_HUB_OFFLINE=1`、`SEED_TTS_WER_EVAL=1`
   - 结果目录：`ACC_BENCH_RESULT_DIR`
10. **优化方向提醒**（PRD 决策树）：TTFT 高 → 预处理/Stage0 排队/图命中；TTFP 高 → 首 codec 窗口/connector/Stage2；RTF 高 → Stage2 NPU 时间/connector 空洞。先 profile（服务级 trace + `msprof`）再动手。

## 三、SSH 长期连接专题（HiDevLab）

### 3.1 为什么总是断

HiDevLab 的 `ssh -J jt_XXX@113.47.8.48:2234 root@199.93.57.13` 中，**`jt_...` 跳板令牌有效期很短**（实测约 30-60 分钟）。令牌过期后：

- 新连接报 `channel 0: open failed: administratively prohibited: platform authorization denied`
- **已建立的 SSH master 连接通常仍可用**（前提：本地未重启、网络未断、master 未退出）
- 目标机密码固定：`ZuVgCRCyHV9yTSCu`（勿写进任何提交文件）

### 3.2 已配置的保活（`~/.ssh/config` Host hidevlab）

```sshconfig
Host hidevlab
    HostName 199.93.57.13
    User root
    Port 22
    IdentityFile ~/.ssh/hidevlab_ed25519
    ProxyJump jt_<最新令牌>@113.47.8.48:2234   # 令牌过期需手动更新
    StrictHostKeyChecking accept-new
    ControlMaster auto          # 复用连接
    ControlPath ~/.ssh/cm-hidevlab-%r@%h:%p
    ControlPersist yes          # master 不因空闲退出
    ServerAliveInterval 30      # 应用层保活
    ServerAliveCountMax 4
    TCPKeepAlive yes
    ExitOnForwardFailure yes
    ConnectTimeout 30
```

### 3.3 推荐工作流（最大化存活时间）

**1. 拿到新令牌后立刻建 master（一次性认证）：**

```bash
# 更新 ~/.ssh/config 的 ProxyJump 行后：
ssh -O exit hidevlab 2>/dev/null          # 清掉旧 master（如有）
DISPLAY=:0 SSH_ASKPASS=/tmp/hidevlab_askpass.sh \
SSH_ASKPASS_REQUIRE=force HIDEVLAB_PASSWORD='<密码>' \
ssh -MNf -o BatchMode=no hidevlab < /dev/null
ssh -O check hidevlab                      # 应输出 Master running
```

`/tmp/hidevlab_askpass.sh` 内容（免交互输密码）：
```sh
#!/bin/sh
printf '%s\n' "$HIDEVLAB_PASSWORD"
```

**2. 后续所有操作走 master（不再触发新认证）：**

```bash
ssh hidevlab '命令'          # 复用 master，令牌过期也能继续
```

**3. 令牌过期后的处理：**

```bash
ssh -O check hidevlab        # 若 master 还在 → 一切照常
# 若 master 已死（No such file or directory / authorization denied）：
# → 需要用户从 WebIDE「连接 → SSH 直连」复制新命令
# → 更新 ~/.ssh/config 的 ProxyJump 行
# → 重新执行第 1 步建 master
```

### 3.4 关键经验

- **远端长任务与 SSH 完全解耦**：所有任务用 `setsid nohup ... &` 启动，日志落 `/workspace/`；SSH 断多少次都不影响任务，只影响「查看进度」。
- **master 是唯一救生艇**：令牌过期后，master 活着就能继续干活；所以拿到新令牌第一件事就是 `-MNf` 建 master。
- **别在命令行里写 pattern 自杀**：`pkill -f "vllm serve"` 会匹配到自身 shell；用 `pkill -f "vllm [s]erve"`。
- **重连后先验证**：`ssh hidevlab 'echo ALIVE; date -u +%FT%TZ'`，再查任务：`tail -c 300 <日志>`、`grep -c "200 OK" <服务日志>`。
- **远端交互会话**（如需）：`tmux new -s minicpm` / `tmux attach -t minicpm`，断线不掉会话。
